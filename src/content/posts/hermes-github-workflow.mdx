## C'est quoi Hermes Agent ?

[Hermes Agent](https://hermes-agent.nousresearch.com/docs) est un agent IA open-source qui tourne sur ton serveur. Il se connecte à tes plateformes (GitHub, Telegram, Discord...) et exécute des tâches avec accès à ton terminal, tes fichiers, et tes outils de dev.

Pour le workflow qui nous intéresse, Hermes expose un **webhook gateway** : il reçoit les événements GitHub et réagit en commentaires sur les issues et PRs.

## Prérequis

- **Un serveur Linux** — un VPS, un NAS, ou même un vieux laptop font l'affaire
- **[Hermes Agent](https://hermes-agent.nousresearch.com/docs)** installé et configuré avec un provider LLM (OpenRouter, Anthropic, etc.)
- **[GitHub CLI](https://cli.github.com/)** (`gh`) installé et authentifié sur le serveur
- **Un dépôt GitHub** public ou avec accès Actions

### 2. Configurer le webhook GitHub

Dans les settings de ton dépôt → **Webhooks** → **Add webhook** :

| Champ | Valeur |
|---|---|
| Payload URL | `https://ton-serveur:PORT/webhooks/rpg-issues` |
| Content type | `application/json` |
| Secret | un secret que tu définis |
| Événements | `Issues`, `Issue comments`, `Pull requests`, `Pull request review comments` |

Hermes validera la signature du webhook — c'est ce qui empêche n'importe qui de déclencher ton agent.

## Configurer Hermes

Dans `~/.hermes/config.yaml` :

```yaml
webhook_subscriptions:
  - id: rpg-issues
    events:
      - issues
      - issue_comment
      - pull_request
      - pull_request_review_comment
    prompt: ~/.hermes/prompts/gh-plan-approve.txt
```

Une seule ligne pour connecter un repo entier. Le prompt (un fichier texte) décrit le comportement attendu : analyser l'issue, proposer un plan, attendre l'approbation, exécuter.

### Le webhook gateway

Hermes Agent expose un endpoint HTTP qui reçoit les webhooks GitHub. Pour chaque événement (`issues`, `issue_comment`, `pull_request`, `pull_request_review_comment`), un **worker webhook** est spawné avec le prompt approprié.

La configuration est déclarative :

```yaml
# ~/.hermes/config.yaml
webhook_subscriptions:
  - id: rpg-issues
    events:
      - issues
      - issue_comment
      - pull_request
      - pull_request_review_comment
    prompt: ~/.hermes/prompts/gh-plan-approve.txt
```

Une ligne pour connecter un repo entier. Le prompt décrit le comportement attendu : analyser l'issue, proposer un plan, attendre l'approbation, exécuter.

## L'anti-loop et la sécurité

Deux protections pour éviter que ça parte en vrille :

* Seul le propriétaire du dépôt peut envoyer des commandes. Un commentaire de n'importe qui d'autre est ignoré.
* Chaque commentaire posté par le bot contient `<!-- hermes -->`. Le webhook ignore les commentaires qui portent ce tag — pas de boucle infinie.

```python
if sender.login != "alshyra":
    return  # Ignorer
if "<!-- hermes -->" in comment_body:
    return  # C'est notre propre message
```
