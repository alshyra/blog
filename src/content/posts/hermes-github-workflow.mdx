**TL;DR** — Copilot Cloud Agent propose un workflow agentique (planifier, implémenter, PR) qui consomme des AI Credits à chaque étape. Hermes Agent fait exactement la même chose — webhook → plan → approve → implémente → merge — sur ton propre serveur. Coût fixe, pas de quota.

---

## Le constat

Depuis le 1er juin 2026, GitHub Copilot est passé en facturation à l'usage. Chaque interaction avec les fonctionnalités agent (Copilot Cloud Agent, agent mode, code review) consomme des GitHub AI Credits. Concrètement :

- **Copilot Pro** : 10$/mois, dont 10$ de crédits AI
- **Copilot Pro+** : 39$/mois, dont 39$ de crédits AI
- **1 crédit AI** = 0,01$ (une seule requête agent peut en coûter plusieurs)

Les complétions de code restent illimitées — ça n'a pas changé. Mais les features *agentiques*[^1] — là où Copilot planifie, réfléchit, exécute en plusieurs étapes — consomment des crédits à chaque tour.

Une après-midi à faire bosser un Cloud Agent sur des issues GitHub, et le budget crédits du mois peut y passer.

[^1]: *Agentique* : un workflow où l'IA ne se contente pas de répondre, mais planifie, exécute des actions, itère jusqu'à un résultat. C'est ce qui différencie un chatbot d'un véritable assistant de développement.

---

## Ce que Copilot Cloud Agent fait de bien, et ce que Hermes reproduit

Copilot Cloud Agent sait :
- Analyser une issue GitHub
- Proposer un plan d'implémentation
- Exécuter les changements
- Ouvrir une Pull Request

Hermes Agent aussi — via un déclencheur webhook, un prompt bien conçu, et un workflow en commentaires GitHub. La différence ? Hermes tourne sur ton infra, pas sur des crédits.

| Fonctionnalité | Copilot Cloud Agent | Hermes Agent |
|---|---|---|
| Analyse d'issue | ✅ crédits | ✅ VPS |
| Plan d'implémentation | ✅ crédits | ✅ VPS |
| Approbation humaine | ✅ "Approve" | ✅ "Hermes approve" |
| Exécution + PR | ✅ crédits | ✅ VPS |
| Review de code | ✅ crédits | ✅ VPS |
| Fix inline | ✅ crédits | ✅ VPS |
| **Coût par tâche** | **variable (crédits)** | **fixe (VPS)** |

### Le webhook gateway

Hermes Agent expose un endpoint HTTP qui reçoit les webhooks GitHub. Pour chaque événement (`issues`, `issue_comment`, `pull_request`, `pull_request_review_comment`), un **worker webhook** est spawné avec le prompt approprié.

La configuration est déclarative :

```yaml
# ~/.hermes/config.yaml
webhook_subscriptions:
  - id: rpg-issues
    events:
      - issues
      - issue_comment
      - pull_request
      - pull_request_review_comment
    prompt: ~/.hermes/prompts/gh-plan-approve.txt
```

Une ligne pour connecter un repo entier. Le prompt décrit le comportement attendu : analyser l'issue, proposer un plan, attendre l'approbation, exécuter.

## L'anti-loop et la sécurité

Deux protections pour éviter que ça parte en vrille :

### Filtre par auteur

Seul le propriétaire du dépôt peut envoyer des commandes. Un commentaire de n'importe qui d'autre est ignoré.

```python
if sender.login != "alshyra":
    return  # Ignorer
```

### Tag anti-boucle

Chaque commentaire posté par le bot contient `<!-- hermes -->`. Le webhook ignore les commentaires qui portent ce tag — pas de boucle infinie.

```python
if "<!-- hermes -->" in comment_body:
    return  # C'est notre propre message
```

## De l'issue à la PR au déploiement

1. Une issue est ouverte (ou un commentaire laissé)
2. Le webhook déclenche Hermes Agent
3. Hermes lit l'issue, comprend le contexte
4. Il poste un plan en commentaire
5. Tu écris `Hermes approve`
6. Hermes implémente, commit, push, ouvre une PR, merge
7. Le push sur `main` déclenche GitHub Actions → déploiement

Tout ça sans terminal, sans crédit consumé.

## Copilot et Hermes : complémentaires

Mon setup aujourd'hui :

- **Copilot** pour les complétions dans l'IDE (ça, c'est illimité, et c'est parfait)
- **Hermes Agent** pour tout ce qui est agentique (issues, PRs, review, correction)

Les deux cohabitent. L'un pour le quotidien dans le code, l'autre pour l'automatisation des tâches GitHub. Et surtout : pas de compteur à surveiller, pas de budget à calculer, pas de "j'ai plus de crédits pour finir ma journée".
